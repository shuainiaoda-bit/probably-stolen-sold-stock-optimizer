# 已售物品优化 0.1.0 测试报告

测试日期：2026-11-17。游戏版本：1.0.0.15，Steam open_beta，构建 26711633。

在这台电脑上，独立 Mod 显著减少了连续大量售卖的交易处理耗时。以下为各场景三轮测试的中位数。

| 售卖量 | 关闭优化 | 启用优化 | 处理速度 | 耗时减少 |
| --- | ---: | ---: | ---: | ---: |
| 1000 件 | 2.416 秒 | 0.216 秒 | 11.2 倍 | 91.0% |
| 2000 件 | 12.501 秒 | 0.497 秒 | 25.1 倍 | 96.0% |

## 测试方法

测试在真实游戏进程中运行，使用 Direct3D11 渲染，分辨率 1280×720。游戏位于隔离桌面，使用后台静音参数。通过临时新存档执行，每件商品为独立物品，80% 为普通矿石、20% 为电线，每件数量为 1。

关闭优化和启用优化交替运行，各做三轮。每轮从空已售仓库开始，重置现金、声望和随机种子，使用同一位不受预算限制的普通顾客。两组保留相同的现有 Mod 组合；测试宿主的连锁经营功能在两组中均关闭。

计时范围为每次原生 `PlayerStore.SellItem` 调用的累计耗时，商品生成、放到柜台、鼠标操作和帧间等待不计入。结果衡量交易处理速度，不能直接换算为画面帧率。

测试宿主通过游戏原生加载器加载最终独立 `SoldStockOptimizer.dll`。发布包与被测 DLL 的 SHA-256 一致。宿主只用于开发测试，发布 Mod 无前置依赖。

## 其他耗时

以下单位为毫秒，各单元格按“关闭优化 / 启用优化”排列。

| 售卖量 | 遍历查询已售物品 | 保存游戏 | 结算并销毁 |
| --- | ---: | ---: | ---: |
| 1000 件 | 15.43 / 0.28 | 169.9 / 169.5 | 706.7 / 753.2 |
| 2000 件 | 37.93 / 0.32 | 368.7 / 308.5 | 5090.5 / 4979.2 |

收益主要集中在售卖和已售物品查询。保存和结算销毁耗时仍受原版流程及物品对象数量影响，本次没有观察到稳定的结算销毁加速。

Unity 的线程分配计数器在本次运行中返回零，因此本报告不据此计算内存节省。

## 功能验证

真实运行时共通过 79 项检查，未捕获运行时错误，包括售卖收入、独立商品数量、物品编号和顺序、交易记录、全部已售物品清理、嵌套容器内容、关闭及重新启用、真实化学品反馈、存读档、次日开门结算。

50 件商品的单独刷新探针中，隐藏已售仓库的物品 UI 刷新从 1325 次降到 50 次。

全部测试完成后，真实存档、设置、原生授权、原有本地 Mod 文件均按文件哈希恢复，创意工坊文件保持一致。新 Mod 另行放入本地 Mods 文件夹，待玩家在游戏中启用。
